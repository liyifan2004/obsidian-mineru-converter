# MinerU 精准解析 API 实操经验总结

> 基于 252 个真实文档（PDF + Word + PPT + Excel + 图片，总计约 80 MB）批量转换的工程经验沉淀。

---

## 一、推荐方案：批量本地文件上传（API 端点选择）

| 场景 | 推荐端点 | 理由 |
|---|---|---|
| **本地文件批量转 Markdown** | `POST /api/v4/file-urls/batch` + `PUT` 上传 + `GET /extract-results/batch/{batch_id}` | 不需要先把文件上传到自己的 OSS 再传 URL 给 API；直接用 API 返回的预签名 URL 上传即可 |
| 文件已经在公网可访问 | `POST /api/v4/extract/task/batch`（URL 批量） | 少一步中转，但 github/aws URL 会被拒 |
| 单个文件 | `POST /api/v4/extract/task` + `GET /extract/task/{task_id}` | 最简，但不适合批量 |

> 我们最终选择的方案是 **`file-urls/batch`**：最省事、最快、避免中转。

## 三、关键经验（坑与解决方案）

### 3.1 速率限制（HTTP 429）

**现象**：
```json
"You have exceeded the 50 files/min limit. Please wait before retrying."
```

**根因**：API 限制每分钟最多提交 50 个文件（包括 `file-urls/batch` 单次最多 50 个）。

**解决方案**：

```python
BATCH_SIZE = 40                  # 不要顶满 50，留缓冲
BATCH_DELAY = 70                 # 批次间隔 70 秒

# 同时在 submit_batch 里加 429 重试逻辑
if response.status_code == 429:
    print("Rate limited. Waiting 65s...")
    time.sleep(65)
    continue
```

**实测**：设 `BATCH_SIZE=40` + `BATCH_DELAY=70s` 稳定通过，100+ 个文件无 429。

> ⚠️ 重要：`response.json()` 在 429 时返回的是字符串，不是 dict。代码里必须做类型检查，否则会出 `AttributeError: 'str' object has no attribute 'get'`。

### 3.2 CDN SSL 下载失败

**现象**：从 `cdn-mineru.openxlab.org.cn` 下载 ZIP 时报：
```
SSLError(SSLEOFError(8, '[SSL: UNEXPECTED_OF_WHILE_READING]'))
```

**根因**：Python `requests` 库 + Windows Schannel 的 SSL 握手问题。`curl`、`urllib` 也都失败。

**解决方案（三种）**：

| 方案 | 适用场景 | 实现 |
|---|---|---|
| **方案 A：PowerShell `Invoke-WebRequest`**（推荐） | 简单场景 | `subprocess.run(["powershell", ...])` |
| **方案 B：curl 加 `--noproxy '*'`** | 系统有代理（如 127.0.0.1:7897）但 CDN 应直连 | `subprocess.run(["curl", "--noproxy", "*", ...])` |
| **方案 C：Python `requests` + verify=False** | 网络隔离环境 | `requests.get(url, verify=False, timeout=60)` |

**推荐方案 A 的核心代码**：

```python
import subprocess, tempfile

def download_zip_ps(zip_url, output_path):
    tmp_zip = os.path.join(tempfile.gettempdir(), f"mineru_{int(time.time()*1000)}.zip")
    ps_cmd = (
        f"try {{ "
        f"Invoke-WebRequest -Uri '{zip_url}' -UseBasicParsing -TimeoutSec 60 "
        f"-OutFile '{tmp_zip}'; "
        f"$size = (Get-Item '{tmp_zip}').Length; "
        f"Write-Output \"OK:$size\" "
        f"}} catch {{ Write-Output \"ERR:$($_.Exception.Message)\" }}"
    )
    result = subprocess.run(
        ["powershell", "-NoProfile", "-NonInteractive", "-Command", ps_cmd],
        capture_output=True, text=True, timeout=90
    )
    output = result.stdout.strip()
    return output.startswith("OK:")
```

### 3.3 代理导致 CDN 连接失败

**现象**：所有下载请求（Python/PowerShell/curl）都失败。

**根因**：系统设置了 `https_proxy=http://127.0.0.1:7897`，CDN 是中国节点（223.100.x.x），本应直连，结果走了国外代理导致 SSL 失败。

**解决方案**：

```bash
# 用 curl 时
curl --noproxy '*' ...

# 或在 Python 里强制不走代理
import os
os.environ['no_proxy'] = '*'
```

**实测**：CDN 直连中国节点速度极快（42.5 MB 几秒下完），绕过代理后 100% 成功。

### 3.4 200 页限制：自动拆分 PDF

**现象**：
```json
{"err_msg": "文件页数超过限制"}
```

**解决方案**：用 PyPDF2 拆分 → 分别提交 → 合并 Markdown。

```python
from PyPDF2 import PdfReader, PdfWriter

def split_pdf(input_path, max_pages=200):
    reader = PdfReader(input_path)
    total = len(reader.pages)
    parts = []
    for start in range(0, total, max_pages):
        writer = PdfWriter()
        end = min(start + max_pages, total)
        for i in range(start, end):
            writer.add_page(reader.pages[i])
        part_path = f"{os.path.splitext(input_path)[0]}_part{(start // max_pages) + 1}of{(total + max_pages - 1) // max_pages}.pdf"
        with open(part_path, "wb") as f:
            writer.write(f)
        parts.append(part_path)
    return parts
```

**合并 Markdown 模板**：

```python
def merge_markdown_parts(parts_dict):
    """parts_dict: {part_idx (0-based): md_content}"""
    merged = []
    for idx in sorted(parts_dict.keys()):
        if len(parts_dict) > 1 and idx > 0:
            merged.append(f"\n\n--- Part {idx + 1} ---\n\n")
        merged.append(parts_dict[idx])
    return "".join(merged)
```

**实测案例**：
- `雅思王听力剑20版.pdf`（322 页）→ 拆成 2 部分 → 合并为 464 KB Markdown
- `雅思口语真经总纲.pdf`（211 页）→ 拆成 2 部分 → 合并为 444 KB Markdown

### 3.5 加密 PDF

**现象**：`简单句结构总结-打开密码123456.pdf` 转换失败。

**根因**：MinerU 不支持密码保护的 PDF。

**解决方案**：先用 PyPDF2 / pikepdf 解密：

```python
from PyPDF2 import PdfReader, PdfWriter

def decrypt_pdf(input_path, password, output_path=None):
    reader = PdfReader(input_path)
    if reader.is_encrypted:
        reader.decrypt(password)
    writer = PdfWriter()
    for page in reader.pages:
        writer.add_page(page)
    output_path = output_path or input_path.replace(".pdf", "_decrypted.pdf")
    with open(output_path, "wb") as f:
        writer.write(f)
    return output_path
```

### 3.6 大小写扩展名

**现象**：`.JPG` / `.DOCX` / `.PPTX` 等大写扩展名文件不会被处理。

**解决方案**：用 `os.path.splitext(f)[1].lower()` 规范化比较：

```python
SUPPORTED_EXTS = {".pdf", ".png", ".jpg", ".jpeg", ".doc", ".docx", ".ppt", ".pptx", ".xls", ".xlsx", ".html", ".htm"}
ext = os.path.splitext(f)[1].lower()
if ext in SUPPORTED_EXTS:
    ...
```

### 3.7 断点续传

**核心思路**：转换前检查目标 `.md` 是否存在，存在则跳过。

```python
md_path = os.path.splitext(full_path)[0] + ".md"
if os.path.exists(md_path) and os.path.getsize(md_path) > 0:
    skipped_md += 1
    continue
```

**好处**：
- 中途中断可继续跑，无需重头开始
- 用户向目录追加新文件后再次运行，只处理增量

### 3.8 `data_id` 用于业务侧匹配

**关键洞察**：批量提交时，API 回传的 `data_id` 是匹配本地文件和 API 结果的唯一可靠方式。

```python
# 提交时
files_data = [{"name": file_name, "data_id": str(i)} for i, file_path in enumerate(files)]

# 轮询时
file_map = {str(i): batch[i] for i in range(len(batch))}
for data_id, er, status in poll_batch_results(...):
    pdf_path = file_map.get(data_id)  # 通过 data_id 反查本地文件
```

> 为什么不用 `file_name`？文件名可能重复，且中文文件名 + API 端编码可能不稳定。`data_id` 是我们自己传的字符串，可控且唯一。

# 主流程
for batch_start in range(0, len(all_files), BATCH_SIZE):
    batch = all_files[batch_start: batch_start + BATCH_SIZE]
